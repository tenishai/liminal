# liminal — repo card

WHAT: MCP gateway. One MCP-over-HTTP connection per agent; many backends behind it (in-process handlers discovered by entry point, plus federated HTTP MCP upstreams), with JWT auth, per-caller handler allowlists, and (sovereign mode) a server-side policy store. Renamed from `limenal` 2026-08; older issues and docs say limenal. The PyPI-style distribution name is `tenish-liminal` since v0.4.0 (`tenishai-liminal` in v0.3.0; pyproject `name`; `liminal.__version__` reads it); the import package and CLI stay `liminal`.
STATE: main, v0.10.0 (pyproject), classifier Pre-Alpha, AGPL-3.0-or-later. CHANGELOG.md has an [Unreleased] section. Active area: federation hardening (multi-issuer trust, policy/admin plane, untrusted-target framing, #108/#110 protected writes, operator-only tools, SSE responses in the client #129/#131, static target `headers` #130, per-persona upstream sessions #172, parent-issuer demotion refusal #87). Every admitted tools/call now writes an access_allow audit row (kind: call) and logs tool.call (docs/arch/policy.md). CHANGELOG [0.10.0] adds GET /admin/cards (every loaded handler's card as written, so a room derives which handlers and scopes a permission opens from the handlers' own labels; #232) and the cabal handler (#189, cabal.inbox); [0.9.3] renders embedded resource blocks in `ToolCallOutcome.text` (#226); [0.9.2] adds `catalog_token_provider` (a bearer for the catalog fetch minted before every fetch by a provider from the `liminal.catalog_tokens` entry-point group, for GitHub's hosted server which refuses an unauthenticated initialize; #225); [0.9.1] reopens a per-persona session an upstream reports lost as a JSON-RPC error (Datadog's hosted server, #224); [0.9.0] adds live targets through the admin plane (`PUT/DELETE/GET /admin/targets`, persisted in the policy DB, the file stays the seed; tenishai/liminal#222); [0.8.0] adds `auth_method = "service-headers"` and `[target.catalog_headers_env]` for targets whose upstream wants a leased key pair in named headers (tenishai/liminal#221); [0.7.1] describes (the bundled `liminal guide` and the `[aws]` extra in the image, tenishai/liminal#213); [0.7.0] added the per-call audit (tenishai/liminal#211); [0.6.0] added the aws handler (#209); later changes go under [Unreleased]. Tags cut by hand; bump pyproject in a PR, tag THAT merge commit (tests/test_version_tags.py; v0.2.0 once shipped reporting 0.1.0, #95).
STACK: Python >=3.12, FastAPI + uvicorn, pydantic v2, joserfc (RS256 JWT), httpx, structlog, stdlib sqlite3 (policy DB only). Optional extras: `[aws]` = `botocore>=1.35` (the `aws` handler imports it lazily and refuses calls without it); `[memory]` = `tenish-techne>=0.18.2` (not on a public index; pair with requirements-sources.txt, which pins the git tag; tests/test_techne_pin.py fails if pyproject, requirements-sources.txt and the Dockerfile's TECHNE_VERSION disagree; the Dockerfile also pins TECHNE_WHEEL_SHA256, and scripts/check-techne-sibling.sh compares commits, run before a sibling-checkout build). Dockerfile present. `pip install -e ".[dev]"`.
ENTRY:
- CLI `liminal` → src/liminal/cli.py:main (`version`, `list-handlers [--cards]`, `serve`, `guide [name]`). `guide` prints src/liminal/docs/<name>.md, listed in liminal.docs.GUIDES and shipped as package data (pyproject `[tool.setuptools.package-data]`; tests/test_bundled_docs.py keeps the two in step)
- server factory → src/liminal/server/app.py:create_app (data plane) + create_admin_app (admin plane on `--admin-port`; takes the data plane's registry for GET /admin/cards)
- JSON-RPC route → src/liminal/server/routes.py (POST /mcp: initialize/ping/tools/list/tools/call; GET /healthz liveness, GET /readyz 503 while degraded; an in-process handler with an optional `status()` reads `unconfigured: …` there, which is not degraded, #191)
- client lib → src/liminal/client/ (AsyncMCPClient/MCPClient read plain-JSON and Streamable-HTTP SSE replies; LibraryLiminalClient, ProxyLiminalClient, from_config)
AUTH MODES (exclusive, cli.py): `--jwks-url` = single-cabal (token's `cabal_scope`/`scope` must contain `dispatch`; token `cabal_tool_extras`/`tool_extras` trusted) | `--trust-registry` + `--policy-db` = sovereign (multi-issuer; token scope/extras IGNORED, grant resolved server-side) | `LIMINAL_AUTH_DISABLED=1` = synthesized claims (identity `anonymous`, scope `[dispatch]`, issuer `local`) and NO JWT verification. With no grant and no token claims, the grant-based scope gate is skipped and the handler allowlist finds no `tool_extras` to restrict by (all handlers allowed). Under auth-off only, `initialize` answers with a fresh `Mcp-Session-Id` header and `tools/call` copies a client's header into `ctx.extra["mcp.session_id"]` (routes.py, #192); the scratchpad keys on it, and it is ignored under auth. Still applied: the secret guard (routes.py; off only via `LIMINAL_SECRET_GUARD`, not by auth-disabled) and the operator-only gate, which refuses every `requires_operator` tool because no caller can prove operator scope. `--jwks-url` and `--trust-registry` together = CLI error exit 2.
BROWSER GUARD (server/request_guard.py, #190): POST /mcp, every mode, before the body is read. `Origin` absent, loopback (localhost/127.0.0.1/[::1], any port) or listed in `LIMINAL_ALLOWED_ORIGINS`, else 403; `null` refused. Content-Type media type `application/json`, else 415. Residual: a page on another loopback origin passes.
REQUEST PATH (routes.py:_handle_tools_call): auth → handler allowlist → per-tool scope gate (sovereign only) → operator-only gate (`requires_operator` tools, EVERY mode) → secret guard (write tools) → credential resolver (sovereign: parent issuer's callers only) → build Context → Multiplexer.dispatch → wire framing (+ `_meta["liminal/untrusted"]` for untrusted targets).

- (uncarded) server/secret_guard.py: shape-based pre-dispatch scan of files.write/memory.commit/notify.send content; fail-closed, ON unless `LIMINAL_SECRET_GUARD` is falsey.
- (uncarded) server/auth.py: JWTVerifier Protocol; URLJWKSVerifier (RS256 pin, iss/aud/exp/iat, needs `cabal_persona`|`persona` AND `sub`), MultiIssuerJWKSVerifier (peeks unverified `iss` only to pick keys).
- (uncarded) handlers/: scratchpad (in-memory per (identity,agent)), files (empty allowlist default; `LIMINAL_FILES_ALLOWED_PATHS`, os.pathsep-separated absolute paths, is a GRANT for a caller with no `files.allowed_paths` claim and a CEILING for one that has the claim; `files.write` to protected paths, hard-linked files and `LIMINAL_FILES_PROTECTED_PATTERNS` matches is refused without `files:protected_writes`), web (host allowlist + private-range SSRF deny), memory (techne), notify (webhook transport), cabal (sends tasks to cabal personas over A2A v1.0 for a person's own MCP agent, #189: one `CABAL_TOKEN_<AGENT>` dispatch token per persona in the caller's credential set is its grant; `send` always returnImmediately; a send that may have arrived without a reply returns `outcome: uncertain` with its contextId; `inbox` lists the caller's input-required tasks across its personas, and contrib/claude-code/cabal_inbox_hook.py surfaces them in a Claude Code session; URL from `LIMINAL_CABAL_A2A_URL` or `LIMINAL_CABAL_URL`, which `serve --cabal-url` exports when unset; docs/cabal-handler.md), aws (read-only AWS through one IAM role per account trusting the gateway's own Google identity over OIDC; accounts from `[tool_extras."aws.roles"]`, an agent reaches `<name>` when its grant holds `<name>:read`; read verbs only, data-plane reads refused by name; admin routes /admin/aws/identity and /admin/aws/probe for a set-up page).

DEPS:
- cabal → liminal: cabal/src/cabal/core/tools/mcp_proxy.py lazily imports `liminal.client.AsyncMCPClient`; cabal's pyproject registers `patterns`/`documents`/`code`/`archivist` into the `liminal.handlers` group; cabal serves `GET /admin/secrets/{persona}/{handler}` and mints the JWTs liminal verifies (single-cabal defaults `--issuer cabal-core`, `--audience liminal`).
- liminal → techne: handlers/memory.py only (lazy `import techne`; module-scope `from techne import VALID_TYPES` is inside try/except with a hardcoded fallback). CI integration job checks out tenishai/techne at the tag the Dockerfile's TECHNE_VERSION pins.
- liminal does NOT call ladon; nothing in src references it.

GOTCHAS:
- Tool names are `<target>.<tool>`; `name.split(".",1)[0]` IS the authz key (allowlist, scope map, credential lookup). Target names must not contain `.` and must not collide with handler names (build_http_targets raises).
- Security defaults are the product: empty files allowlist, SSRF deny list, fail-closed malformed allowlist (→ deny all). Never widen one to make a test pass.
- Untrusted-result authority is `_meta["liminal/untrusted"]` + nonce, NOT the `[BEGIN UNTRUSTED TOOL RESULT]` banner text.
- `admin:*` does NOT grant `files:protected_writes` (handlers/files.py, `PROTECTED_WRITE_SCOPE in ctx.granted_scopes`, explicit membership). Outside sovereign mode `ctx.granted_scopes` is empty, so `files.write` to a protected path is always refused. Protected: instruction files (CLAUDE.md, AGENTS.md, GEMINI.md, .cursorrules, .windsurfrules, .clinerules, .roorules, ...), `.mcp.json`, `.claude.json`, `.vscode/mcp.json`, `.github/copilot-instructions.md`, anything under `.claude/`, `.cursor/`, `.git`, `.gemini/`, `.roo/`, `.clinerules/`, `.github/instructions/`, `.cline/rules/`, `.windsurf/rules/`, `.devin/rules/`, any existing regular file with more than one hard link, and anything matching an operator pattern from `LIMINAL_FILES_PROTECTED_PATTERNS` (adds to the built-ins, cannot remove; a pattern protects what it matches and everything beneath it, so `/` protects the whole tree). The hard-link check is narrowed, not closed: a link made after the write's open-time re-check and before the write ends is not caught (#108, #110).
- `pythonpath = ["src"]` in pyproject makes pytest test THIS tree, not the editable install (#85, fix on main via #88). Outside pytest the editable install still wins; use `PYTHONPATH=$PWD/src`.
- The stdio target transport is config-validated but NOT served (build_http_targets rejects non-http: "only 'http' is supported in Stage A", target/http.py).
- STATUS.md is a 2026-06-11 snapshot that labels itself "HISTORICAL SNAPSHOT ... not maintained"; docs/design.md labels itself "ORIGINAL PROPOSAL — the implementation diverged". Trust code over both.
