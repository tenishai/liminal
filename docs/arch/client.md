# client — MCP client library other repos import

WHAT / SEAM: `liminal.client` (client/__init__.py). AsyncMCPClient / MCPClient (client/mcp.py): initialize, list_tools → list[Tool], call_tool(name, args) → ToolCallOutcome(content, is_error, .text) (only AsyncMCPClient.call_tool takes extra_headers=), ping, aclose (MCPClient, the sync twin, has `close`). Errors: MCPError base; MCPTransportError (network failure, 5xx, a body that is not a JSON object, or an event stream that ends without the reply) (subclass MCPSessionExpired: 404 on a request carrying a session) vs MCPRemoteError(code, message, data) (JSON-RPC error body; `code` is coerced to an int). DEFAULT_PROTOCOL_VERSION "2025-06-18". `LiminalClient` Protocol (client/protocol.py) unifies LibraryLiminalClient (in-process) and ProxyLiminalClient (HTTP wrapper of AsyncMCPClient); `from_config({"mode": "library"|"proxy", ...})` picks one.
OPS / FLOW: handshake auto-runs on first authenticated call; `token_provider` callable is invoked per request so short-lived JWTs refresh transparently. POSTs JSON-RPC to `<base_url>/mcp` with `Accept: application/json, text/event-stream`. If the server answers `text/event-stream` the client reads events until the one whose JSON-RPC `id` matches the request (notifications and server requests on the stream are skipped); plain JSON replies work as before (#129, #131). After the reply it keeps reading the rest of the stream for up to `sse_drain_timeout` seconds (constructor arg, default `DEFAULT_SSE_DRAIN_TIMEOUT` 0.5; `0` disables, so it stops at the reply and the connection is not reused) so the connection can go back to the pool (#132, #138). If the stream has not ended by then the connection is closed instead: the async client cancels the read via anyio and closes the response, the sync client starts a `threading.Timer` that shuts the socket down at the deadline. A transport with no socket (httpx.MockTransport) is not drained on the sync path. `static_headers` (constructor arg, dict) go on every request including the handshake and catalog fetch; the client's own headers (Authorization only when a token is sent, Accept, Content-Type, Mcp-Session-Id) win on a case-insensitive name collision, and per-call `extra_headers` (AsyncMCPClient.call_tool only; the sync client has none) are applied last (#135). `auth_scheme` (constructor arg, `"bearer"` default | `"basic"`) sets how the token rides `Authorization` on every request, `initialize` and notifications included: bearer sends `Bearer <token>`, basic sends `Basic base64(<token>)` with the token as `user:secret`. `authorization_value(scheme, token)` is the one encoding rule; `_auth_header` and HttpTarget's per-call service-token header both call it, and an unknown scheme raises ValueError. `use_session=True` keeps the `Mcp-Session-Id` from `initialize` and sends it on later requests; it is OFF by default, because a client shared across callers must stay stateless (#76, #129). HttpTarget turns it on only for `session="per-persona"`, with one client per persona (#172). A 404 on a request that carried a session raises `MCPSessionExpired` (an MCPTransportError subclass) and, if that session is still the client's current one, drops it and marks the client uninitialized so the caller can initialize and retry; a session a concurrent call already replaced is left alone. `AsyncMCPClient.initialize(extra_headers=)` sends per-call headers on the handshake and the `initialized` notification, so a session opens with its caller's credential. `AsyncMCPClient.terminate_session()` sends DELETE with the session id, best effort, and forgets it. `initialized` is a read-only property.
INVARIANTS:
- Library mode is "same process, same trust": it bypasses the HTTP route, so NO JWT, handler allowlist, scope gate, secret guard, or untrusted `_meta`. Use proxy mode wherever isolation matters.
- Library mode converts results with `to_spec_result_content` (the same function the HTTP route uses), so a `ToolResult.failure` message (`.error`) reaches the caller as text content alongside is_error=True (#66, #114). tests/test_liminal_client_protocol.py:test_library_failure_message_reaches_the_caller asserts it.
- Keep MCPTransportError vs MCPRemoteError distinct: HttpTarget maps them to different refusal reasons, and cabal catches by type.
CONSUMERS: cabal/src/cabal/core/tools/mcp_proxy.py (lazy `from liminal import client`; AsyncMCPClient, ToolCallOutcome); target/http.py (HttpTarget wraps AsyncMCPClient for upstreams). Tests: test_client.py, test_client_sse.py, test_client_sse_pool.py, test_liminal_client_protocol.py, test_client_auth_header_omitted.py, test_basic_auth_scheme.py, test_stateful_upstream.py.
