# targets — Multiplexer + federated MCP upstreams

WHAT / SEAM: `Target` Protocol (target/base.py): name, trust (TrustTier TRUSTED|UNTRUSTED), startup/shutdown, async list_tools (UNprefixed), dispatch(tool, payload, ctx), protocol_version. Impls: InProcessTarget (wraps a Handler, always TRUSTED), HttpTarget (one HTTP MCP upstream via AsyncMCPClient; an upstream that replies with SSE is read by the client, #131). `Multiplexer` (dispatch/multiplexer.py) holds targets by name, prefixes `{name}.{tool}`, routes by `partition(".")`. InProcessDispatcher (dispatch/local.py) is the older registry-only twin, still used by LibraryLiminalClient.
CONFIG: `liminal serve --targets targets.toml` → `[[target]]` tables → `TargetSpec` (target/config.py): name, transport http|stdio, command (stdio argv, required for stdio), address (base URL WITHOUT /mcp; client appends it, #69), trust (default untrusted), on_untrusted flag|strip|block, identity forward|none, auth_method bearer|service-token|service-headers|none, bearer_token or bearer_token_env (exactly one required when auth_method=bearer; mutually exclusive; bearer_token_env with any other auth_method is refused), auth_scheme bearer|basic (default bearer; basic needs auth_method bearer or service-token), credential_key, credential_headers (header name -> ctx.credentials key; required non-empty with auth_method=service-headers, refused otherwise), catalog_headers_env (header name -> env var; with service-token or service-headers only; #221), client_name, required_scope, tool_scopes, headers (static request headers, http only), session none|per-persona (http only, default none; #172), timeouts, refresh interval (300s). An unknown `[[target]]` key is a TargetConfigError, which includes `relevance_signals` (removed, #136).
OPS / FLOW: lifespan → Multiplexer.startup → HttpTarget connects, initializes, fetches catalog → `inspect_catalog` (target/inspect.py) scans UNTRUSTED catalogs for override phrases, hidden/bidi unicode, >1024-char descriptions, schema >10k nodes or >64 deep → applies on_untrusted. Background refresh re-fetches. Dispatch → per-call headers (`x-liminal-persona`, `x-liminal-issuer` if identity=forward; `Authorization` from ctx.credentials if service-token, encoded per auth_scheme; one named header per `credential_headers` entry from ctx.credentials if service-headers; `x-correlation-id` always) → upstream → UNTRUSTED results wrapped by `frame_untrusted_result` (nonce-tagged banner, hidden unicode stripped from every string, to depth `MAX_CONTENT_DEPTH` = 64 in inspect.py; deeper content raises UnsanitizableResult, which becomes a refusal) and flagged `liminal_untrusted*` → routes.py copies to `_meta`.
INVARIANTS:
- `tool_name.split(".",1)[0] == target.name == registry key` is the authz key for allowlist, scope map and credentials. Guarded by tests/test_dispatch_contract.py. Target names: non-empty, no `.`, no collision with handlers or each other (TargetConfigError).
- `headers` (#130, #135, #141): http only (a stdio spec with headers is refused); values must be strings with no CR, LF or NUL; names must be RFC 9110 tokens as written (no stripping, so " X-Foo " is refused at load, not by h11 on the first request); names are case-insensitive and two names differing only by case are refused; any name in `RESERVED_HEADERS` (target/config.py: authorization, x-liminal-persona, x-liminal-issuer, x-correlation-id, mcp-session-id, accept, content-type) is refused. HttpTarget passes them to its AsyncMCPClient as `static_headers`, so they ride `initialize`, catalog fetch and every call, and the client's own headers win a collision.
- Only `transport="http"` is served; stdio specs validate but build_http_targets rejects them ("Stage A"). stdio + identity forwarding is rejected at config time (children cannot carry per-request identity).
- Per-call headers are built fresh and NEVER stored on the shared client (#13), so persona A's token cannot ride persona B's request. With `session="none"` (default) the shared client keeps `use_session` off, so an upstream `Mcp-Session-Id` is never kept or echoed (#129; tests/test_http_target.py).
- `session="per-persona"` (#172): the base client keeps its own session for the catalog fetch only; each dispatch goes through `_call_in_session`, which keeps one AsyncMCPClient per verified `(issuer, identity)` in `_sessions` (an OrderedDict, LRU past `MAX_PERSONA_SESSIONS` = 256). A persona's client is initialized with that call's per-call headers (its credential, identity and correlation id) under a per-key asyncio.Lock, so concurrent first calls open one session; calls themselves are not serialized. `MCPSessionExpired` (404 on a sent session) reopens once and retries; a second 404 is a transport-error refusal. The catalog refresh reopens its own expired session the same way. Shutdown sends DELETE, one after another, for every session `_sessions` still holds plus the catalog session, before closing the HTTP client. A session evicted by the LRU cap is dropped without a DELETE and expires on the upstream's clock (#174). A session id lives on exactly one client object, so it cannot ride another persona's call; tests/test_stateful_upstream.py seeds per-persona sentinel credentials and asserts no request carries both, and no session carries two personas' credentials (#93).
- Static credential (auth_method=bearer) rides every base call, `initialize` first, encoded per `auth_scheme` by the client (`Basic base64(user:secret)` for basic). `bearer_token_env` is read in `HttpTarget.startup` before any client is built; unset, empty or whitespace-only raises RuntimeError naming the variable, so the target is a startup failure on /healthz, never an anonymous upstream call (tests/test_basic_auth_scheme.py).
- Missing or whitespace-only service-token credential → refusal ToolResult, never an unauthenticated upstream call (#80).
- service-headers (#221): `_build_call_headers` sets every `credential_headers` entry from ctx.credentials, fresh per call; any one missing or whitespace-only → the same refusal. `catalog_headers_env` is resolved in `HttpTarget.startup` (`_catalog_headers`, RuntimeError naming the variable when unset) and passed as the CATALOG client's static headers only (`_new_client(static_headers=...)`); persona session clients get `spec.headers` alone, so a shared catalog credential never rides a persona's call. Both tables are validated by `TargetSpec._check_header_table` (field-name token, case-insensitive dedupe, RESERVED_HEADERS) plus: no name shared with static `headers`, env values must be identifiers, neither on stdio (tests/test_service_headers.py).
- One target's startup failure does not stop the others (#86); it stays registered and /healthz (always 200) and /readyz (503 while degraded, #159) report `degraded` with one of "startup failed", "catalog fetch failed (startup|refresh)", "catalog inspection failed (startup|refresh)" or "not started". A failed catalog = zero tools, visible on /healthz (#75).
- Consumers must trust `_meta["liminal/untrusted"]` + nonce, not the banner text (an upstream can imitate text).
- Unsanitizable upstream content → refusal ToolResult naming target and cause, not an exception.
- A target that raises → `ToolResult.failure("<target>.<tool> raised <Class> (error id <8 hex>)")` via `raised_failure` (dispatch/local.py, shared with InProcessDispatcher). The same id is on the `multiplexer.target_raised` / `dispatch.handler_raised` log line with the exception message; the message never reaches the caller (#193; tests/test_dispatch_error_id.py). Not yet the per-request correlation id of #27.
- Owned httpx client rejects all cookies (#76).
- Target scopes are operator config only (see policy.md); declaring tool_scopes makes the target deny-by-default.
CONSUMERS: server/app.py:create_app (builds all targets), server/routes.py (dispatch, /healthz, /readyz, `_meta`). Tests: test_http_target.py, test_untrusted_result_framing.py, test_catalog_depth_bound.py, test_cli_targets.py, test_tool_extras_forwarding.py, test_basic_auth_scheme.py, test_stateful_upstream.py, test_target_header_validation.py, test_readyz.py, test_service_headers.py.
